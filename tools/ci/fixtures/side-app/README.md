# System split test fixture (not BitChord)

For an isolated disposable API27 emulator only. This small Activity deliberately uses the supported dev package so the production app-launch path can be tested without distributing BitChord binaries. Do not install it on a user's device or replace an actual developer build. The APK is not bundled in iDash or committed here. Its visible UI explicitly says it is a test fixture, not BitChord.

Compile this Java source against android.jar, dex with D8, package this manifest with aapt and sign the resulting APK with the emulator debug key. Install it on the isolated emulator before DriveSideSmoke. Enable the minimal DriveSideActions service using shell test settings. DriveSideSmoke uses UiAutomation with FLAG_DONT_SUPPRESS_ACCESSIBILITY_SERVICES, rebinds the service after instrumentation restarts the target process, opens the dedicated side Activity, verifies real multi-window state, live clock, no map/browser allocation and two separate visible top Activity task windows. It then captures the complete native window. Restore prior accessibility settings and uninstall the fixture after testing. The committed rc4 native screenshot is from this fixture; actual BitChord remains a hardware test.
